# /slop-clean — remove AI slop from current branch changes

Strip AI-generated code smells (useless comments, over-defensive guards, excessive nesting) from files that the current branch changed against `{baseBranch}`. One agent per file in parallel; one critical review pass at the end. Read-only on anything not touched by the current branch.

> **Scope:** this command edits code. It is a write operation. It is **not** a substitute for `/review` — `/review` is read-only defect finding; `/slop-clean` removes a specific class of cosmetic smells. Run `/slop-clean` first, then `/review`, then `/push`.

## Modes

Parse `$ARGUMENTS` once at entry:

- **(default — no flag)** **`branch-diff` mode** — scope is files changed in HEAD vs `{baseBranch}` merge-base. Interactive: Step 2 asks the user to confirm before dispatch. Use this from the terminal when you want to clean your in-progress branch before `/push`.
- **`--staged`** — scope is files in the staging area only (`git diff --cached --diff-filter=AM --name-only`). Non-interactive: Step 2 is skipped (the caller — typically `_cycle.md` step 5 between `git add` and `git commit` — already decided). The review pass in Step 5 walks `git diff --cached`, not the branch diff.

Anything other than the empty argument list or exactly `--staged` → print `error: /slop-clean accepts no argument or --staged` and exit.

## Step 0: Load project config

§ `${CLAUDE_PLUGIN_ROOT:-$HOME/.claude}/commands/ticket/_config.md`.

JIRA settings are optional for this command. If `jira.enabled` is `false` or absent, continue — `/slop-clean` only needs `{baseBranch}` and `{maxConcurrent}` (default `3`, max `5`).

## Step 1: Identify changed files

**branch-diff mode (default)**:

```bash
git fetch origin --quiet
MERGE_BASE=$(git merge-base "origin/{baseBranch}" HEAD)
git diff --diff-filter=AM "$MERGE_BASE"..HEAD --name-only
git rev-parse --show-toplevel
```

**`--staged` mode**:

```bash
git diff --cached --diff-filter=AM --name-only
git rev-parse --show-toplevel
```

(`--staged` skips the `origin/{baseBranch}` fetch — the staging area is local-only.)

Filter the file list:

- **Drop** paths matching any of: `node_modules/`, `dist/`, `build/`, `.next/`, `out/`, `coverage/`, `__snapshots__/`, files ending in `.lock`, `.lockb`, `.min.js`, `.min.css`, `.snap`, `.map`, lockfiles like `package-lock.json`, `pnpm-lock.yaml`, `bun.lockb`, `yarn.lock`, `Cargo.lock`, `Gemfile.lock`, `composer.lock`.
- **Drop** binary or non-text files (use `file --mime-encoding` if uncertain).
- **Drop** `messages/*.tsv`, `*.po`, `*.mo` translation tables — flagged as out-of-scope to slop heuristics.
- **Drop** any file whose first line begins with `AUTO-GENERATED` or `Code generated by` (run `head -n 1` per file).

If the resulting list is empty:

- branch-diff mode → print `slop-clean: no changed files to inspect against {baseBranch} — exiting.`
- `--staged` mode → print `slop-clean (--staged): no staged files — exiting.`

…and stop.

## Step 2: Confirm with the user

**`--staged` mode skips this step entirely** and proceeds straight to Step 3 with the full filtered list. The caller (typically `_cycle.md`) already decided.

**branch-diff mode**:

Present:

- Total files to scan (count and the list itself).
- The merge-base commit short SHA.
- Estimated parallel batches: `ceil(files / {maxConcurrent})`.

Ask via `AskUserQuestion` (single question):

> **Proceed with `/slop-clean` on N files? Each file gets one `slop-cleaner` agent in parallel.**
>
> - **Proceed** — run all files now.
> - **Subset** — let me pick a subset by index (you list files numbered, ask again with a multi-select).
> - **Cancel** — abort the command.

On `Cancel`, exit without changes. On `Subset`, present a multi-select `AskUserQuestion` listing the files; carry only the chosen subset into Step 3.

## Step 3: Parallel agent dispatch

For each file in the (possibly narrowed) list, dispatch:

```
Agent(
  subagent_type="slop-cleaner",
  description="slop-clean: <file>",
  prompt=<see below>,
  run_in_background=false
)
```

Prompt body to each agent:

```
file_path: <absolute file path>
repo_root: <absolute repo root from git rev-parse --show-toplevel>

Apply the slop-clean skill in full. Edit the file in place. Return the report shape defined in the skill.
```

**Parallelism**: launch up to `{maxConcurrent}` Agent calls in a single message, then wait for all to return before launching the next batch. Do not start a second batch until every agent in the previous batch has reported.

If a single agent returns an `error:` (refused — generated file, multi-path, etc.), record it for the final report and continue with the rest. Do not abort the whole command.

## Step 4: Aggregate per-file results

Build a table:

| File | Removed | Skipped | Out-of-scope | Status |
|---|---|---|---|---|
| ... | ... | ... | ... | ok / refused / blocker |

Sum the totals. Save the per-file `Removed` and `Out-of-scope findings` sections from each agent report — the final report (Step 6) renders them.

## Step 5: Critical review pass

Run the review pass yourself (the main session, not a subagent). Re-fetch the cumulative diff — **the diff scope must match the mode**:

**branch-diff mode**:

```bash
git diff "$MERGE_BASE"..HEAD --stat
git diff "$MERGE_BASE"..HEAD
```

**`--staged` mode**:

```bash
git diff --cached --stat
git diff --cached
```

Walk the diff against this checklist:

**Safety**
- [ ] No removed line was the only path that handled an error from I/O / network / DB / subprocess / parsing.
- [ ] No removed line was a guard at a system boundary (HTTP body, env var, file content, external API response).
- [ ] No public export (function name, class name, React component name, route handler signature, exported type) changed.
- [ ] No type annotation was deleted.
- [ ] All intent directives (`@ts-expect-error`, `eslint-disable-*`, `noqa`, `type: ignore`, `biome-ignore`) still present.

**Behaviour**
- [ ] Return values, throws / rejections, and side effects of every touched function still match the pre-edit version.
- [ ] No imported symbol turned unused (run `git diff` and grep for `import .* from` lines to confirm — if so, that is fine; just verify the symbol is genuinely unused now).
- [ ] BDD test markers (`#given` / `#when` / `#then`) preserved.

**Project rules** (aesthetic-clinic specifics — see project `AGENTS.md`)
- [ ] No hard-coded user-facing string introduced or revealed.
- [ ] No CSS color literal introduced where a Tailwind token was.
- [ ] No cross-feature import added or "cleaned up" into existence.
- [ ] No server-component → client-component (or reverse) flip.

For any failed checkbox:

1. Identify the offending hunk and the file.
2. Decide: **revert that hunk** (preferred) **or** apply a corrective edit.
3. To revert a single hunk safely without losing other edits in the same file (branch-diff mode):
   ```bash
   git diff "$MERGE_BASE"..HEAD -- <file> > /tmp/slop-<basename>.patch
   # Open /tmp/slop-<basename>.patch, drop the offending hunk, then:
   git checkout "$MERGE_BASE" -- <file>
   git apply /tmp/slop-<basename>.patch
   ```
   In `--staged` mode, the equivalent is `git restore --staged --worktree -- <file>` to drop the offending edits from both index and working tree, then re-stage anything you want to keep.
4. Re-run the relevant checkbox.

If a check still fails after one corrective pass, surface it under **Unresolved issues** in Step 6's report and leave the edit reverted.

## Step 6: Final report

Print one markdown block, in **English**, suitable to paste into a PR description (branch-diff) or a commit-time log line (`--staged`):

```
## /slop-clean report

**Mode**: branch-diff | --staged
**Scope**: <current branch> vs <baseBranch>@<merge-base short sha>   (branch-diff)
       OR  staged index of <current branch>@<HEAD short sha>          (--staged)
**Files inspected**: N
**Files edited**: M
**Total candidates**: T
**Removed**: R   |   **Skipped (safety)**: S   |   **Out-of-scope findings**: Z

### Per-file summary
| File | Removed | Skipped | Out-of-scope |
|---|---|---|---|
| <path> | <n> | <n> | <n> |

### Highlights — what was removed
- <category>: <file>:L<line> — <one-line excerpt before → after>
- ...

### Out-of-scope findings (no edit applied)
- <file>:L<line> — <i18n / color-token / module-boundary / type-safety / other>: <description>

### Review pass
- Safety: PASS / FAIL (<which check>)
- Behaviour: PASS / FAIL (<which check>)
- Project rules: PASS / FAIL (<which rule>)

### Unresolved issues (if any)
- <file>:L<line> — <reason a corrective pass could not be applied automatically>
```

After printing the report:

- **branch-diff mode** — leave the working tree as-is. **Do not commit.** The user runs `/push` (or their normal commit flow) afterward and chooses what to include.
- **`--staged` mode** — leave both the index and working tree as-is. The caller (typically `_cycle.md` step 5) handles re-staging and the `git commit`. **Never commit from inside this command.**

## Notes

- v0.2.5 shipped this as a fully manual command. v0.2.6 adds the `--staged` mode so `_cycle.md` can wire it in via the `skillIntegration.slopCleanBeforeCommit` toggle (default OFF — high time cost on every commit, like `simplifyBeforeCommit`).
- The `slop-cleaner` agent must be called **exactly once per file**. Never bundle multiple paths into a single agent call — the agent will refuse.
- If `{baseBranch}` is not present in `.claude/project.json`, the loader defaults to `"main"`. Aesthetic-clinic ships with `"develop"`; verify before running on a fresh checkout. (`--staged` mode does not consult `{baseBranch}`.)
- The command writes files but never runs lint, tests, or builds. Run those (or `/review`) afterwards.
